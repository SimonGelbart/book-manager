# Domain documentation

Use one root CONTEXT.md glossary and docs/adr/ for architectural decisions.

Before exploring, read the glossary and ADRs relevant to the work.
Proceed when these files do not yet exist.

Use the glossary's terminology consistently. Surface contradictions with
existing ADRs explicitly.

Create glossary entries as terms are settled. Keep implementation details
in specifications and architecture notes.

Create ADRs when decisions are costly to reverse, need context to
understand, and reflect a real trade-off.
